# 7. GAPS

**Hardware/kernel facilities present but unobservable with current tooling:**
- **NVMe health/SMART:** `nvme0` is live and bound, but no `nvme-cli` → no way to query SMART log, namespace/health info. *Closes with:* `nvme-cli`.
- **RAPL/energy:** `intel_rapl_msr`, `intel_rapl_common`, and `rapl` kernel modules **are loaded**, and dmesg shows the RAPL perf PMU registered a `psys` domain — KVM is exposing RAPL MSRs. But `/sys/class/powercap/` is empty (no `intel-rapl` zone directories got created) and `/dev/cpu/*/msr` doesn't exist (the `msr` module isn't loaded) and no `turbostat`/`powercap` reader is installed — so despite kernel-level RAPL support existing, there is currently no userspace path to read power/energy. *Closes with:* `linux-cpupower` (turbostat) + `modprobe msr` (`msr-tools`).
- **DMI/SMBIOS detail:** raw DMI strings are readable directly under `/sys/class/dmi/id/*`, but structured/decoded SMBIOS tables (e.g. memory slot population, which dmesg shows as "Memory slots populated: 1/1" but nothing decodes further) aren't inspectable. *Closes with:* `dmidecode` (and `lshw` for a consolidated view).
- **perf counters:** CPU reports `arch_perfmon` in its flag set, but no `perf` binary is installed to actually use it. *Closes with:* `linux-perf-6.12` (or the generic `linux-perf` meta-package matching this kernel).

**Instrumentation genuinely ABSENT from this VM (hypervisor hiding it, not a missing package)** — verified by checking that the kernel found *zero* underlying devices/controllers to bind to, which a tool install cannot fix:
- No `/sys/class/hwmon` directory at all → no sensor chips exposed by KVM; `lm-sensors` would find nothing.
- No `/sys/devices/system/edac` → no virtual memory-controller EDAC device; Nitro doesn't pass through real DIMM error reporting to the guest.
- `thermal_zone*` entries: none exist, only two stub `cooling_device{0,1}` ACPI processor-cooling objects with no backing temperature sensor — no real thermal zone was ever registered.
- No `/sys/firmware/efi` → this instance boots BIOS/legacy mode, so no EFI variable/runtime-services introspection is possible (not hidden, genuinely not in use for this boot).
